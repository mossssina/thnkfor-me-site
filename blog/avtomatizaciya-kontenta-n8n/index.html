Автоматизация контента:
Claude + n8n + Notion
в одной связке

Октябрь 2026 THNKFOR.ME ~1 900 слов

Производство контента — это не творчество, это производство. И как любое производство, оно автоматизируется. Разбираем схему, которую мы используем для клиентов: от темы до публикации без ручного труда на каждом этапе.

Что даёт связка

Claude генерирует текст с глубоким пониманием контекста. n8n — оркестрирует весь поток данных. Notion — хранит базу знаний и контент-план. Вместе они заменяют 3–4 часа ручной работы в день.

Почему n8n, а не Make или Zapier

n8n — open-source инструмент автоматизации, который можно развернуть на собственном сервере. Это важно для контент-маркетинга по трём причинам: отсутствие лимитов на объём данных, возможность хранить API-ключи локально, полный контроль над логикой без ограничений тарифного плана.

Make.com проще в освоении, но дорожает при масштабе — каждый «сценарий» тарифицируется. n8n при том же объёме задач стоит фиксировано ~$20/мес на собственном VPS. Для контент-завода с сотнями задач в месяц разница существенная.

Для небольших проектов (до 50 публикаций/мес) Make.com — нормальный выбор. Для серьёзной автоматизации — n8n.

Архитектура системы

Наш стек состоит из трёх уровней: хранение и планирование (Notion), оркестрация (n8n), генерация (Claude API + Midjourney). Каждый уровень выполняет свою функцию и может быть заменён альтернативой.

Настройка Notion как базы знаний

Notion выполняет роль «мозга» системы: хранит бренд-голос, стоп-слова, примеры удачных и неудачных постов, контент-план. Claude читает эти данные через Notion API при каждой генерации.

Структура базы данных в Notion:

База «Контент-план»: поля — Тема, Платформа, Формат, Статус (Идея/В работе/Готово/Опубликовано), Дата публикации, Ключевые слова, Ссылка на результат.

База «Бренд-голос»: тон, запрещённые слова, примеры хороших постов по форматам (информационный, продающий, UGC-стиль), список хэштегов по рубрикам.

База «Исследования»: статьи конкурентов, данные по ключевым словам, инсайты из аналитики — всё, что Claude использует как контекст.

Ключевой приём

Не давайте Claude «пустой» промпт. Каждый запрос на генерацию должен включать: бренд-голос из Notion, 2–3 примера хороших постов, конкретную тему и целевую аудиторию. Это поднимает качество с «сойдёт» до «отлично».

Схема n8n воркфлоу

Воркфлоу запускается ежедневно в 8:00 по расписанию. Он берёт из Notion задачи со статусом «Готово к генерации», запускает Claude для каждой, сохраняет результат обратно в Notion и добавляет в очередь публикации.

Узлы воркфлоу:

Узел 1 — Cron Trigger: запуск по расписанию (каждое утро или по вебхуку при добавлении задачи).

Узел 2 — Notion: Get Tasks: получение записей из базы «Контент-план» со статусом «В генерации». Фильтр: `Status = "В генерации" AND Date = today`.

Узел 3 — Notion: Get Brand Voice: загрузка текущего бренд-гайда и примеров постов. Это контекст для Claude.

Узел 4 — Claude API (HTTP Request): отправка промпта с задачей + контекстом. Модель: claude-sonnet-5 или claude-opus-5 для сложных форматов. Промпт включает: тему, бренд-голос, формат, целевую платформу, требуемую длину.

Узел 5 — Notion: Update Record: сохранение сгенерированного текста, заголовка, хэштегов обратно в запись. Статус меняется на «Готово к проверке».

Узел 6 — Telegram: Notify Editor: редактор получает уведомление с текстом и кнопками «Принять» / «На доработку». Один клик — контент уходит в очередь публикации.

Промпт-архитектура для Claude

Промпт — это главная переменная качества. Вот структура, которую мы используем:

# Системный промпт (не меняется) Ты — копирайтер бренда [НАЗВАНИЕ]. Тон: {brand_voice из Notion} Стоп-слова: {stop_words из Notion} Примеры хороших постов: {examples из Notion} # Пользовательский промпт (меняется для каждого поста) Тема: {topic} Платформа: {platform} — ВКонтакте / Telegram / Instagram* Формат: {format} — информационный / продающий / сторис Аудитория: {audience} CTA: {call_to_action} Длина: {length} символов

Разделение системного и пользовательского промпта позволяет использовать кэширование промптов в Claude API (prompt caching) — это снижает стоимость генерации на 70–90% при больших объёмах.

Контроль качества

Полностью автоматическая публикация без редактора — риск. Правильная схема включает человека на финальной проверке, но минимизирует его время.

01
Первичный AI-фильтр
После генерации Claude сам проверяет текст по чек-листу: нет стоп-слов, длина соответствует, есть CTA, соблюдён тон. Тексты с ошибками отправляются на повторную генерацию автоматически.
02
Быстрая проверка редактором
Редактор в Telegram-боте видит текст и нажимает ✅ или ✏️. Цель — не переписывать, а проверить факты и тон. В среднем 30–60 секунд на пост.
03
Метрики и обучение
n8n собирает данные о постах: охват, ER, клики. Каждую неделю лучшие посты автоматически добавляются в базу примеров для Claude. Система самообучается на реальных данных.

Стоимость системы

Для типичного клиента с объёмом 100 постов в месяц:

Claude API: ~$15–40/мес в зависимости от модели и длины постов. claude-haiku-4-5 дешевле в 20 раз, подходит для простых форматов. claude-sonnet-5 — для лонгридов и стратегического контента.

n8n (self-hosted VPS): ~$5–15/мес за VPS + бесплатно n8n community.

Notion: $8/мес на человека. Для команды из 3 человек — $24/мес.

Итого: $45–80/мес против зарплаты копирайтера от 60 000 ₽/мес. При этом объём контента — 100+ единиц против 30–40 у специалиста.

Важно понять

Система не заменяет стратега и редактора — она убирает рутину генерации и форматирования. Один человек с AI производит столько контента, сколько раньше требовало команды из 3–4.

С чего начать

Минимальный жизнеспособный вариант за 1–2 недели:

1. Создайте базу в Notion: контент-план + бренд-голос (5–6 часов работы). 2. Настройте n8n на хостинге Render.com (бесплатный tier) или $5/мес VPS. 3. Подключите Claude API ($5 за тест первых 200 постов). 4. Настройте один воркфлоу: Notion → Claude → Telegram-уведомление. 5. Запустите с 10 постами в неделю, постепенно увеличивая объём.

Полная система с SMMplanner, мониторингом метрик и самообучением — второй этап, через 4–6 недель после запуска базовой версии.
